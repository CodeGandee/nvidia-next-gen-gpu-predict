# Topic Environment Gate: nvidia-next-gen-dc-gpu-v2

## Purpose

本主题环境用于收集和规范化公开的 LLM、NVIDIA 数据中心 GPU/平台与 GPGPU 研究证据，构建按历史决策时点截断的双时间戳面板数据，实现“可行域 + 多目标决策 + 多输出统计观测”的数学模型、滚动历史回测和概率预测，并以中文为主生成调查报告。本文件只描述后续环境意图，不授权安装软件、拉取仓库或执行 GPU 试验。

## Runnable Requirements

- 支持通过 Isomer/Kaoju 记录网页、技术报告、论文、数据表、来源身份、证据冻结日期和审计状态。
- 支持解析和验证 CSV、JSON、YAML、Markdown 与 PDF 中的结构化规格数据。
- 支持带事件时间、首次公开时间、采集时间和来源版本的双时间戳数据处理，能够按每个历史世代的规格冻结时点执行无未来泄漏的数据截断。
- 支持受约束优化、稀疏多输出回归、贝叶斯分层或状态空间模型、逻辑/生存模型、滚动历史留出回测、概率校准、区间预测、敏感性分析和图表生成。
- 支持可行域检查、参数/变量数量审计、先验或正则化记录、缺失数据处理、基线模型、分组消融和可复现实验配置。
- 支持在不依赖 v1 文件或产物的条件下，独立运行 v2 的数据处理、模型验证和报告构建流程。
- 初始建题和文献调查应可在 CPU 环境完成；任何 CUDA 微基准、模拟器或本机 GPU 试验都必须由后续独立的 trial 流程定义并授权。

## Expected Repositories

- 当前没有用户指定的外部代码仓库、分支、提交或克隆命令。
- GPGPU-Sim、Accel-Sim、GPU 微基准或模型服务框架仅是潜在后续研究对象；若调查需要摄取或运行代码，应先固定仓库身份、许可证、不可变版本和资源边界。
- 不得把 `nvidia-next-gen-dc-gpu-v1` 工作区或其 Topic Main 当作 v2 的代码或数据来源。

## Data and Source Requirements

- 仅使用可合法访问的公开资料，优先选择 NVIDIA 官方数据表与架构资料、模型发布方技术报告、论文原文、同行评审出版物和可复核代码仓库。
- 为动态网页与路线图信息记录抓取日期、发布日期、产品状态和原始 URL，并区分正式规格、初步规格、演示结果和营销比较。
- 为每条模型输入同时记录事件发生时间、首次公开可得时间、采集时间、适用世代和可用性证据；历史回测只能使用早于目标世代冻结时点的记录。
- 规格数据必须保留单位、精度、稠密/稀疏口径、芯片/单卡/节点/机架层级、脚注和缺失值，不得在摄取时静默换算或填补。
- 模型数据必须显式区分直接观测、由原始数字推导的变量、代理变量、区间估计和不可观测变量，并保留每次转换公式。
- 当前未授权私有数据、受限数据集、付费凭证或厂商保密材料；遇到访问、许可证或再分发边界时必须停止并请求用户决定。

## Runtime and Resource Assumptions

- 使用项目规定的 Pixi 环境执行仓库自有 Python、检查和测试命令。
- 初始预测模型固定为可解释的受约束结构模型与小样本统计层组合；除非历史回测证明必要性，不使用高维黑箱或深度学习预测器。
- 数学模型实现必须能够固定随机种子、输入快照、特征版本、模型配置和回测折叠，并输出机器可读的预测分布与误差记录。
- 若后续需要 GPU，必须先发现并记录实际硬件、驱动、CUDA、显存、功耗与运行限制，不得假定特定型号可用。
- 网络检索可以用于发现和获取公开证据，但正式结论必须经过 Kaoju 的获取、检查和审计边界。

## Success Criteria

- v2 Workspace Runtime 可用，主题源意图和派生材料可通过语义路径解析。
- 数据处理与预测代码能够从固定版本输入重建每个世代的 $\mathcal{I}_g$、技术可行域、规格标签、滚动回测、基线比较、消融、预测分布和图表。
- 每个历史世代的预测只能使用其规格冻结时点之前的数据，并能自动检测违反时间截断的特征泄漏。
- 数学模型必须报告参数、约束、有效样本量、可辨识性、MAE/对数误差/sMAPE、区间覆盖率以及离散特性的 Brier score 或等价校准指标。
- 只有当模型相对上一代沿用、CAGR 和单变量趋势基线表现出稳定的样本外改进时，才允许形成定量下一代预测。
- 每项关键规格与特性预测都能追溯到输入证据、模型版本、假设、误差和反证条件。
- 中文主报告可以在不读取或修改 v1 工作区的情况下独立生成。

## Open Setup Questions

- 后续是否需要真实 GPU 微基准来校准带宽、互连或算力利用率代理变量？
- 是否需要引入 GPGPU-Sim/Accel-Sim 等模拟器，还是仅检查其论文和公开结果即可？
- 数据覆盖审计后需要决定受约束决策层与统计观测层的最小可辨识参数化，但不得退化为无约束趋势外推。
- 需要为各历史世代确定可审计的规格决策/冻结日期代理，并评估替代日期定义对回测结果的敏感性。
- 若需要构建 PDF 或 Wiki，应在论文/导出流程中另行确认模板和本地构建授权。
